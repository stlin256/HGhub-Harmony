# RECSYS-SPEC：离线推荐与端侧智能（实施 SPEC）

> 依据：上游交付包 `hghub-recsys-deliverable`（README + docs/OFFLINE-RECSYS.md v1.7）
> 适用工程：`harmony/`（API 26 / HarmonyOS 7）
> 状态：实施中（M0.5 + M1.5：池优先 + 静默目录同步）
> 关联文档：`docs/harmony/RECSYS-TODO.md`（任务清单）、`docs/harmony/DESIGN.md`

## 1. 目标

为 HGhub-Harmony 提供**端侧个性化推荐**，以本地目录池为核心：

1. **池优先**：预置目录包（3,388 条）+ **后台静默目录同步** + 增量池作为候选，摆脱"单页 14 条随机打乱"；
2. **允许后台网络**：客户端可在后台**限速、串行、静默**地抓取公开目录（feed / 分类 / 榜单），
   刷新本地目录与热度先验；请求可配置、可关闭、失败静默；
3. **可降级**：目录包/画像/同步任一失败时回退热门/随机，不影响可用性；
4. **隐私**：用户画像与行为只落本地，不上传；后台抓取只请求公开内容。

## 2. 范围

| 本期 | 后续里程碑（见 TODO） |
|---|---|
| 预置目录包载入（3,388 条标签/热度） | RDB 事件表 + 7 天衰减 + 时段画像 |

| 池内加权随机采样接入首页 | 冷启动预热、曝光回流、本地评估页 |
| 推荐开关 + 诊断（目录/画像/同步状态） | 端侧模型（可选） |

**不包含**：云端训练、跨用户协同过滤、账号体系、商业化。

## 3. 数据资产与同步策略

| 资产 | 大小 | 处理 |
|---|---|---|
| `catalog_pack.json` | 183 KB | **随包**（`rawfile/recommend/`），启动异步载入，作为冷启动基座 |
| `genre_dict.json` | 26 KB | **随包**，标签词典（直采 + 关键词匹配） |
| `catalog_index.json` / `corpus_full.jsonl` | 1.3MB / 3.9MB | 不随包、不提交（开发分析用） |

**后台目录同步（RecSync）**：

| 项 | 规则 |
|---|---|
| 触发 | 首次启动后延迟执行；之后每 24h 或每次冷启动（距上次 ≥6h）；可被设置页关闭 |
| 目标 | `Api.feed(page)` 前 N 页 + 4 个分类各 1–2 页（只读公开接口） |
| 频率 | 串行，页间隔 ≥1.2s；单次请求硬上限 60；失败不重试（下次再试） |
| 处理 | 新条目 → 端上打标（词典直采/关键词）→ 合并进本地目录（去重 by id）→ 保存增量文件 |
| 存储 | `filesDir/recsys/catalog_extra.json`（仅增量，预置包不动）；后续迁移 RDB |
| 首页 | 推荐采样使用「预置包 + 增量」；Hero 仍按 new_at/last_ep_at 取"最新上线" |

```text
        ├─ RecDict.ets        genre_dict 载入、标签名/别名查找、简单关键词打标
        ├─ RecProfile.ets     画像权重（指数衰减）、事件更新、防抖持久化
        ├─ RecSync.ets        后台静默目录同步（串行、限速、可关）
        └─ RecTypes.ets       类型与常量

```

## 5. 关键设计决策

1. **保留"换一批"体感**：按画像权重加权随机采样（无放回），而非固定 Top-N；Hero 维持"最新上线"。
2. **允许后台抓取但必须克制**：单次 ≤60 请求、串行 1.2s、24h 冷却、失败静默、设置页可关；
   只请求公开目录接口，不携带/不采集任何用户数据。
3. **M0.5 不引入 RDB**：画像与增量目录先用 preferences/文件；RDB（items/events/profile）放后续里程碑。
4. **种子画像**：收藏 +3.0、点赞 +1.5、历史 +1.0 映射到标签，保证首日个性化。
5. **端上打标最小版**：词典直采（tags → id）+ 关键词覆盖（title/desc 子串命中 L2/L3），
   置信度、每层上限、总上限 12；AC 自动机与 n-gram 向量属 P2。
6. **降级**：目录包缺失/损坏 → 仅用增量；同步失败 → 保留旧目录；画像为空 → 热度+随机。

## 6. 排序公式（本期）

```text
score = 0.55·affNorm + 0.25·pop + 0.10·fresh + 0.10·jitter
affNorm = min-max(Σ 画像权重[item.labels])
pop     = 目录热度（归一化 0..1；增量条目用 feed 位置/榜单先验，缺失取 0.5）
fresh   = new_at/last_ep_at 7 天内为 1，线性衰减；缺失 0.5
jitter  = Math.random()
```

采样权重 `w = exp(score / T)`，默认 `T = 0.35`，无放回抽取。

## 7. 验收（本期）

| 编号 | 场景 | 预期 |
|---|---|---|
| R01 | 首次启动（无本地数据） | 不崩溃；推荐≈热度+随机，仍能出内容 |
| R02 | 有收藏/历史 | 推荐池中同标签内容占比高于随机（诊断可见 Top 标签） |
| R03 | 连续"换一批" | 每批内容/顺序不同，且整体向偏好标签倾斜 |
| R04 | 目录包缺失/损坏 | 回退随机/增量，首页可用 |
| R05 | 播放/收藏后 | 画像权重上升，下次采样更偏向该标签 |
| R06 | 后台目录同步 | 首次/间隔触发；串行限速；新条目入库，诊断目录数增加；失败静默 |
| R07 | 设置关闭同步/推荐 | 不再发起目录请求 / 回退随机 |
| R08 | 性能 | 3,388 条采样 < 5 ms；启动载入不阻塞首帧 |
| R09 | 隐私 | 画像只写本地；抓取不携带 token/账号信息 |

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 后台抓取被站点限流/封禁 | 串行 1.2s、单次 ≤60、24h 冷却、失败静默、可关闭 |
| 动态标签（0xF000 露骨行为类） | 不写入静态词典，画像只存 ID |
| 单用户样本小 | 权重衰减 + 裁剪；后续 Wilson/最小样本 |
| 预置包解析耗时 | 180 KB 首帧后异步；失败降级 |
| 信息茧房 | 10% jitter + 后续 MMR/探索 |
